# 0001-review-never-blocks-the-task-run

Prompt Review は Task Run を遅延させず、エージェントが受け取るテキストも変更しない。レビュー結果は表示と Sink にだけ流れる。

## 理由

同期評価を選ぶと、送信のたびにレビュー完了を待つことになる。1件あたり1〜3秒でも、1日に何十回も送る前提ではその待ち時間が作業手順の一部になり、「ついで」ではなく「手順」になる。手順になった時点でオフにされ、学習機会はゼロになる。

プロンプトを書き換えてエージェントに渡す設計（repair）は、意図の改変リスクを持つ。`the bug of login` を `the login bug` に直すのは無害に見えるが、書き換えの判断はモデルに委ねられ、誤った解釈をそのままタスク内容に変えてしまう。タスクの失敗は学習ツールへの信頼を一度で失わせる。

さらに repair は学習の向きを逆にする。学習に必要なのは「自分が何を書いたか」と「到達形」の差分であり、自分が書いた側を見えなくすると、その差分そのものが観察できなくなる。

## 代替案

- **同期評価（送信前に待つ）**: フィードバックを必ず読ませられるが、タスクを毎回待たせる。
- **repair（書き換えて渡す）**: エージェントが誤解しにくくなる代わりに、意図改変と学習機会の喪失を招く。
- **オンデマンドのみ（`/lingua:check`）**: 干渉ゼロだが「ついで」が成立せず、叩かれなくなる。
